I just completed implementing split view for the Token text editor (all 7 phases). The feature allows splitting editor groups horizontally/vertically, with tabs and shared documents.

Key implementation details:
- EditorArea contains documents (HashMap by DocumentId), editors (HashMap by EditorId), groups (HashMap by GroupId), and a LayoutNode tree
- LayoutNode is either Group(GroupId) or Split(SplitContainer with direction, children, ratios)
- compute_layout() recursively assigns rects to groups
- group_at_point() and splitter_at_point() handle hit testing
- EditorArea::single_document() is the migration helper creating EditorArea from Document + EditorState
- Documents are shared across views; each EditorGroup has tabs referencing EditorIds

Layout operations implemented in update.rs:
- split_focused_group() / split_group() - create new group with same document
- insert_split_in_layout() - update layout tree
- close_group() / remove_group_from_layout() - remove groups and collapse tree
- collect_group_ids() - traverse layout for ordered list
- focus_adjacent_group() - cycle through groups
- move_tab() / close_tab() - tab management

Current test coverage (tests/layout.rs has 17 tests):
- Split operations: horizontal, vertical, multiple splits, new editor for same document
- Close group: last group protection, cleanup, layout collapse
- Focus: direct, next/prev, by index, invalid group

- Integration: edit in split view affects both
