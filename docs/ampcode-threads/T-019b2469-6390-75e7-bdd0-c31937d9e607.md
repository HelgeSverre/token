Section Title: []() tiny-xlib
Content:
A tiny set of bindings to the [Xlib](https://en.wikipedia.org/wiki/Xlib) library.
The primary contemporary library for handling [Xlib](https://en.wikipedia.org/wiki/Xlib) is the [`x11-dl`](https://crates.io/crates/x11-dl) crate. However, there are three
primary issues.
**You should not be using Xlib in 2023.** [Xlib](https://en.wikipedia.org/wiki/Xlib) is legacy code, and even that doesn't get across
how poor the API decisions that it's locked itself into are. It has a global error hook for
some reason, thread-safety is a mess, and it has so many soundness holes it might as well be made
out of swiss cheese. You should not be using [Xlib](https://en.wikipedia.org/wiki/Xlib) . If you _have_ to use [Xlib](https://en.wikipedia.org/wiki/Xlib) , you should just
run all of your logic using the much more sound [XCB](https://xcb.freedesktop.org/) library, or, even more ideally, something
like [`x11rb`](https://crates.io/crates/x11rb) . Then, you take the `Display` pointer and use it for whatever legacy API you've
locked yourself into, and use [XCB](https://xcb.freedesktop.org/) or [`x11rb`](https://crates.io/crates/x11rb) for everything else. Yes, I just called [GLX](https://en.wikipedia.org/wiki/GLX) a legacy API. It's the 2020's now. [Vulkan](https://www.khronos.org/vulkan/) and [`wgpu`](https://crates.io/crates/wgpu) run everywhere aside from legacy machines.
Not to mention, they support [XCB](https://xcb.freedesktop.org/) .

Section Title: []() tiny-xlib
Content:
Even if you manage to use [`x11-dl`](https://crates.io/crates/x11-dl) without tripping over the legacy API, it is a massive crate. [Xlib](https://en.wikipedia.org/wiki/Xlib) comes with quite a few functions, most of which are unnecessary in the 21st century.
Even if you don't use any of these and just stick to [XCB](https://xcb.freedesktop.org/) , you still pay the price for it.
Binaries that use [`x11-dl`](https://crates.io/crates/x11-dl) need to dedicate a significant amount of their binary and memory
space to the library. Even on Release builds, I have recorded [`x11-dl`](https://crates.io/crates/x11-dl) taking up to seven
percent of the binary.
Global error handling. [Xlib](https://en.wikipedia.org/wiki/Xlib) has a single global error hook. This is reminiscent of the Unix
signal handling API, in that it makes it difficult to create well-modularized programs
since they will fight with each-other over the error handlers. However, unlike the signal
handling API, there is no way to tell if you're replacing an existing error hook.
`tiny-xlib` aims to solve all of these problems. It provides a safe API around [Xlib](https://en.wikipedia.org/wiki/Xlib) that is
conducive to being handed off to both [XCB](https://xcb.freedesktop.org/) APIs and legacy [Xlib](https://en.wikipedia.org/wiki/Xlib) APIs. The library only
imports absolutely necessary functions. In addition, it also provides a common API for
handling errors in a safe, modular way.

Section Title: []() Features
Content:
Safe API around [Xlib](https://en.wikipedia.org/wiki/Xlib) . See the [`Display`](https://docs.rs/tiny-xlib/latest/tiny-xlib/struct.Display.html) structure.
Minimal set of dependencies.
Implements [`AsRawXcbConnection`](https://docs.rs/as_raw_xcb_connection/latest/as_raw_xcb_connection/trait.AsRawXcbConnection.html) , which allows it to be used with [XCB](https://xcb.freedesktop.org/) APIs.
Modular error handling.

Window management.
