- I ran the existing divan benchmarks (cargo bench main_loop, cargo bench rendering) and documented results
- The realistic_typing_with_newlines benchmark showed ~845ms for 10 lines with render - this is the major bottleneck
- I identified several allocation-heavy hot paths causing performance issues:

Key bottlenecks I found:
- word_start_before / word_end_after in src/update/document.rs lines 25-72 - these allocate ENTIRE document prefix/suffix as String just to iterate characters for word boundary detection
- RopeBuffer::line() in src/editable/buffer.rs lines 296-305 - double allocation (to_string + trim_end_matches().to_string())
- move_word_left/right in src/editable/state.rs lines 357-390 and 424-451 - collects entire line content into Vec<char>
- last_non_whitespace_column in src/editable/buffer.rs line 351 - unnecessary string collection

# Performance Analysis Methodology and Findings

## Methodology

The performance investigation followed these steps:

1. **Establish Baseline:** Run existing benchmarks (`cargo bench main_loop`) to establish a baseline.
2. **Profiling:** Use `samply` to capture CPU profiles on a release build compiled with debug symbols (`cargo build --profile profiling`).
3. **Bottleneck Identification:** Analyze benchmark results and profiling data to pinpoint slow functions, focusing on text editing paths.

## Identified Bottlenecks

### 1. String Allocations in Word Navigation (Critical)

**Location:** `src/update/document.rs` lines 25-72 (`word_start_before` and `word_end_after`)

```rust
// word_start_before - allocates ENTIRE prefix as String
fn word_start_before(buffer: &ropey::Rope, offset: usize) -> usize {
    let text: String = buffer.slice(..offset).chars().collect(); // ALLOC
    let chars: Vec<char> = text.chars().collect();               // ALLOC
    // ...
}

// word_end_after - allocates ENTIRE suffix as String
fn word_end_after(buffer: &ropey::Rope, offset: usize) -> usize {
    let text: String = buffer.slice(offset..).chars().collect(); // ALLOC
    let chars: Vec<char> = text.chars().collect();               // ALLOC
    // ...
}
```

**Impact:** For a 100K line file, `word_start_before` at position 50K allocates ~2.5MB just to find the word boundary.

### 2. RopeBuffer::line() Double Allocation

**Location:** `src/editable/buffer.rs` lines 296-305

```rust
fn line(&self, line: usize) -> Option<Cow<'_, str>> {
    let line_slice = self.rope.line(line);
    let s = line_slice.to_string();                           // ALLOCATION 1
    let trimmed = s.trim_end_matches(&['\n', '\r'][..]).to_string(); // ALLOCATION 2
    Some(Cow::Owned(trimmed))
}
```

**Impact:** Every line access allocates twice. Called frequently during rendering and word navigation.

### 3. EditableState Word Movement Allocations

**Location:** `src/editable/state.rs` lines 357-390 and 424-451

```rust

```

### 4. last_non_whitespace_column String Collection

**Location:** `src/editable/buffer.rs` line 351

```rust
fn last_non_whitespace_column(&self, line: usize) -> usize {
    let line_slice = self.rope.line(line);
    let s: String = line_slice.chars().collect();  // UNNECESSARY ALLOCATION
    let trimmed = s.trim_end_matches(|c: char| c.is_whitespace());
    trimmed.chars().count()
}
```

## Recommended Optimization Priority

1. **High Impact, Low Effort:** Fix `word_start_before` / `word_end_after` to use iterators
2. **High Impact, Medium Effort:** Add lazy line iteration to avoid `Vec<char>` allocations
3. **Medium Impact, Low Effort:** Fix `last_non_whitespace_column` to iterate in reverse
4. **Medium Impact, Medium Effort:** Optimize `RopeBuffer::line()` to avoid double allocation
5. **Low Impact, High Effort:** Add dirty rect tracking to rendering
