### Find & Replace Modal Rendering Bug Details

#### **Symptoms and Observations**
*   **Vertical Clipping**: The modal was vertically truncated, cutting off the bottom of the "Replace" input field and leaving no padding. Standard action buttons (Replace, Replace All) were missing or obscured.
*   **Right Border Detachment**: A 1-pixel vertical gap existed between the modal's dark background fill and the light gray border line.

*   **Corner Integrity**: The bottom-right corner was not closed; the vertical and horizontal border lines did not meet due to the 1-pixel outward shift and downward overshoot.

#### **Screenshot Reference**
*   **File**: `website/src/assets/screenshots/screenshot-showcase-find-replace.png` (generated via `screenshots/scenarios/showcase-find-replace.yaml`).

#### **Code Locations**
*   **Rendering Logic**: `src/view/mod.rs` within the `render_modals` function (specifically the `ModalState::FindReplace` case starting around line 2179).
*   **Geometry Calculation**: `src/view/geometry.rs` in the `modal_bounds` function (line 827).
*   **Drawing Primitive**: `src/view/frame.rs` in the `draw_bordered_rect` function (line 242).

#### **Root Causes and Fixes**

**1. Height Calculation Error**
*   **Issue**: The `extra_height` calculation for the Find & Replace modal was 12px too short. It used `line_height + 12 + line_height + 4`, which failed to account for the full padding/spacing required by the input fields.
*   **Fix**: Modified `src/view/mod.rs` to increase the padding constant from `+4` to `+16`:
    ```rust
    // src/view/mod.rs
    let extra_height = if state.replace_mode {
        line_height + 12 + line_height + 16 // label + spacing + replace field + padding
    } else {
        0
    };
    ```

**2. Alpha Blending and Border Misalignment**
*   **Issue**: The Fleet Dark theme uses a semi-transparent overlay background (`#181818E0`). The `draw_bordered_rect` function was using `fill_rect_px`, which performed a raw ARGB stamp rather than blending. This caused the translucent background to composite differently than the opaque border, creating a visual gap and "detached" appearance in the PNG output.
*   **Fix**: Updated `draw_bordered_rect` in `src/view/frame.rs` to use `blend_rect_px` for the fill and forced the border to be opaque:
    ```rust
    // src/view/frame.rs
    pub fn draw_bordered_rect(...) {
        // Fill background (blend to handle semi-transparent overlay backgrounds)
        let alpha = (fill_color >> 24) & 0xFF;
        if alpha == 0xFF {
            self.fill_rect_px(x, y, w, h, fill_color);
        } else {
            self.blend_rect_px(x, y, w, h, fill_color);
        }

        // Draw border (1px on each edge, always opaque)
        let opaque_border = border_color | 0xFF000000;
        self.fill_rect_px(x, y, w, 1, opaque_border); // Top
        self.fill_rect_px(x, y + h.saturating_sub(1), w, 1, opaque_border); // Bottom
        self.fill_rect_px(x, y, 1, h, opaque_border); // Left
        self.fill_rect_px(x + w.saturating_sub(1), y, 1, h, opaque_border); // Right
    }
    ```

pub fn modal_bounds(window_w, window_h, line_height, has_list, list_items) -> (x,y,w,h)
```

It’s fundamentally the source of drift: it has no idea what the modal will actually render.

Replace it with:

- `geometry::modal_layout(model, modal_state) -> ModalLayout`
  (or one function per modal: `find_replace_layout(...)`, `command_palette_layout(...)`, etc.)

### Step 1: Introduce a tiny vertical stack layout helper (pure geometry)
Add to `geometry.rs` something like:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum ModalWidgetId {
    Title,
    FindLabel,
    FindInput,
    ReplaceLabel,
    ReplaceInput,
    ResultsList,
    // etc per modal
}

#[derive(Clone, Debug)]
pub struct ModalLayout {
    pub outer: Rect,                  // modal background + border
    pub content: Rect,                // padded content area inside outer
    pub widgets: std::collections::HashMap<ModalWidgetId, Rect>,
}

#[derive(Clone, Copy, Debug)]
pub struct LayoutCtx {
    pub line_height: usize,
    pub scale_factor: f64,
    // (optionally) char_width if you want width decisions based on it
}

#[derive(Clone, Copy, Debug)]
pub struct Spacing {
    pub pad: usize,       // outer padding
    pub gap: usize,       // generic gap between stacked items
    pub gap_small: usize, // smaller gap (e.g., title->body)
}

pub struct VStack {
    x: usize,
    y: usize,
    w: usize,
    cursor_y: usize,
    widgets: std::collections::HashMap<ModalWidgetId, Rect>,
}

impl VStack {
    pub fn new(x: usize, y: usize, w: usize) -> Self { /* ... */ }

    pub fn gap(&mut self, h: usize) { self.cursor_y += h; }

    pub fn push(&mut self, id: ModalWidgetId, h: usize) -> Rect {
        let r = Rect::new(self.x as f32, self.cursor_y as f32, self.w as f32, h as f32);
        self.widgets.insert(id, r);
        self.cursor_y += h;
        r
    }

    pub fn height_used(&self) -> usize { self.cursor_y - self.y }
}
```

Key point: **height becomes `vstack.height_used()`**, i.e., “what we actually laid out”.

### Step 2: Centralize widget heights (especially TextField height)
Right now your drift is largely “layout thinks input height is X, renderer draws input as Y”.

You already have a `TextFieldRenderer`. Give it a pure helper used by geometry:

```rust
impl TextFieldRenderer {
    pub fn height_px(line_height: usize, opts: &TextFieldOptions) -> usize {
        // single source of truth for vertical padding/border/etc
        line_height + (opts.padding_y * 2) + opts.border * 2
    }
}
```

Then layout code uses `TextFieldRenderer::height_px(...)` instead of `line_height + 8`-style guesses.

### Step 3: Each modal builds its own layout from its state (Find-only vs Replace)
Example: **Find/Replace** becomes:

```rust
pub fn find_replace_layout(
    window_w: usize,
    window_h: usize,
    ctx: LayoutCtx,
    is_replace: bool,
    results_count: usize,
) -> ModalLayout {
    let modal_w = (window_w as f32 * 0.5).clamp(300.0, 500.0) as usize;

    let spacing = Spacing { pad: 12, gap: 8, gap_small: 4 };

    let content_w = modal_w.saturating_sub(spacing.pad * 2);

    // First pass: measure by building from y=0
    let mut v = VStack::new(0, 0, content_w);

    v.push(ModalWidgetId::Title, ctx.line_height);
    v.gap(spacing.gap_small);

    v.push(ModalWidgetId::FindLabel, ctx.line_height);
    let tf_h = TextFieldRenderer::height_px(ctx.line_height, &TextFieldOptions::default());
    v.push(ModalWidgetId::FindInput, tf_h);
    v.gap(spacing.gap);

    if is_replace {
        v.push(ModalWidgetId::ReplaceLabel, ctx.line_height);
        v.push(ModalWidgetId::ReplaceInput, tf_h);
        v.gap(spacing.gap);
    }

    // list height derives from data, not a separate “extra_height” in render code
    let max_visible = 8usize;
    let visible = results_count.min(max_visible);
    if visible > 0 {
        let list_h = visible * ctx.line_height + 8;
        v.push(ModalWidgetId::ResultsList, list_h);
    }

    let content_h = v.height_used();
    let modal_h = content_h + spacing.pad * 2;

    let modal_x = (window_w - modal_w) / 2;
    let modal_y = (window_h / 4).min(100);

    // Second pass: translate all rects into final coordinates
    let content_x = modal_x + spacing.pad;
    let content_y = modal_y + spacing.pad;

    let mut widgets = std::collections::HashMap::new();
    for (id, r) in v.widgets {
        widgets.insert(
            id,
            Rect::new(r.x + content_x as f32, r.y + content_y as f32, r.width, r.height),
        );
    }

    ModalLayout {
        outer: Rect::new(modal_x as f32, modal_y as f32, modal_w as f32, modal_h as f32),
        content: Rect::new(content_x as f32, content_y as f32, content_w as f32, content_h as f32),
        widgets,
    }
}
```

**No `base_height` + `extra_height` split exists anymore**, so Find-only vs Replace can’t drift: the layout pass is the truth.

### Step 4: Rendering uses only `ModalLayout`
In `render_modals()`, replace hand-calculated `y + 8`, `y + line_height + 4`, etc. with:

- draw modal background using `layout.outer`
- draw title at `layout.widgets[Title]`
- draw inputs using `layout.widgets[FindInput]`, etc.

This makes your render code much smaller: it becomes “draw widget in rect”.

### Step 5: Hit-testing uses only `ModalLayout`
In `hit_test_modal()`, instead of calling `modal_bounds()` + re-deriving internals:

- call the same `find_replace_layout(...)`
- `inside = layout.outer.contains(pt.x, pt.y)`
- optional: for richer hit targets, check `layout.widgets[FindInput].contains(...)`, etc.

This completely removes the duplicated `extra_height` logic between render + hit-test.

## 3) Rationale and trade-offs

### Why this works
- **Single source of truth**: the same layout pass defines sizes/positions for both rendering and hit-testing.
- **Automatic height**: modal height becomes the sum of the widgets you actually lay out (including conditional sections like Replace mode and results list).
- **Consistent spacing**: you encode spacing once (`Spacing`) and reuse it across all modals.
- **Small-project friendly**: it’s just a `VStack` and a couple of structs—no framework, no dependency.

### Trade-off
You’ll write a little boilerplate per modal to map modal state → widgets, but that’s *good* boilerplate: it replaces fragile pixel math spread across rendering and hit-test.

---

## 4) Risks and guardrails

- **Risk: TextField height still drifts** if the renderer draws padding/borders not reflected in geometry.
  Guardrail: make `TextFieldRenderer::height_px(...)` (or equivalent) the *only* place that defines its height, and use it in both layout + rendering.

- **Risk: “two-pass” translate step bugs** (layout at origin then translate).
  Guardrail: keep the API explicit: “measure at (0,0), then translate by (content_x, content_y)”. Or bake translation into `VStack::new(content_x, content_y, w)` and just do one pass.

- **Risk: widget ID HashMap overhead/verbosity**.
  Guardrail: for each modal, you can define a small struct instead of a `HashMap` once things stabilize:
  `FindReplaceLayout { outer, title, find_input, replace_input: Option<Rect>, ... }`.
  Start with `HashMap` for speed of refactor; specialize later if desired.

---

## 5) When to consider the advanced path
Only if you later need:
- horizontal layout (label + input on same row),
- dynamic wrapping text,
- scrollable areas inside modals,
- alignment (right-align buttons), etc.

If you hit those, add **one** extra primitive: `HBox` or `Row { left_fixed, right_fill }`. Don’t jump to a full constraint solver.

---

enum Node {

```

`measure(node) -> height` and `place(node, x, y, w) -> widgets`.
This keeps conditional layout super clean (just build a Node tree), but it’s not necessary to fix your current problems—`VStack` is enough.

- **`ModalLayout`** — computed layout with outer bounds + absolutely-positioned widget rects, shared by rendering and hit-testing

- **Per-modal layout functions**: `find_replace_layout()`, `goto_line_layout()`, `command_palette_layout()`, `file_finder_layout()` — each builds a VStack with the modal's specific content, and height is derived from what's actually laid out

**Key improvement:** Height can never drift from content because both are computed in the same VStack pass. The old `modal_bounds()` + `extra_height` pattern is eliminated. Hit-testing calls the same layout functions as rendering — single source of truth.

- **`VStack::push()` / `height()`**

  That’s the usual, correct convention for pixel rect hit-testing and matches typical “width/height” rendering semantics (covering `[x, x+w)` not including `x+w`). No off-by-one.
