I've been working on a Rust text editor (Token) with an Elm-style architecture using winit for windowing.

Recent work completed:
- Fixed undo/redo bugs: Cmd+Z was typing 'z' instead of triggering undo on macOS because the keybinding used ctrl instead of (ctrl || logo). Fixed by adding logo modifier support.
- Added atomic Replace EditOperation for selection replacement so undo restores both deleted text and inserted text in one operation
- Implemented Cmd+D duplicate line/selection feature
- Added status bar click capture so clicks on status bar don't propagate to editor
- Created comprehensive monkey_tests.rs with 23 edge case tests for fuzzing

Key patterns I've established:
- TDD approach: write failing tests first, then implement
- Use saturating_sub for viewport calculations to prevent overflow panics
- Keybindings use (ctrl || logo) for cross-platform Cmd/Ctrl support
- Character input is blocked when ctrl or logo is held: !(ctrl || logo)
- EditOperation enum has Insert, Delete, and Replace variants for undo/redo
- Tests go in tests/ directory with common/ module for shared helpers

Technical details:
- Messages flow through Msg enum -> update() function
- DocumentMsg for text operations, EditorMsg for cursor/selection, AppMsg for window events
- model.editor.viewport.visible_lines can be 0 during extreme window resizes - must use saturating_sub
- Status bar occupies bottom line_height pixels of window
- Renderer has is_in_status_bar(y) method to check if click is in status bar area

All 227 tests pass including the new monkey tests.
