I created a centralized config_paths module (src/config_paths.rs) as the single source of truth for all config directory paths:
- config_dir() returns ~/.config/token-editor/ on Unix/macOS, %APPDATA%\token-editor\ on Windows
- keymap_file() returns the keymap.yaml path
- config_file() returns the config.yaml path
- themes_dir() returns the themes subdirectory
- ensure_all_config_dirs() creates the directory structure

I explicitly avoid using dirs::config_dir() on macOS because it returns ~/Library/Application Support - we want XDG-style ~/.config instead. The implementation respects XDG_CONFIG_HOME if set.

I removed wrapper functions that just forwarded to config_paths and updated all callers to use config_paths directly:
- Removed theme::get_config_dir(), theme::get_user_themes_dir()
- Removed keymap::defaults::get_user_config_path()
- Removed EditorConfig::config_path(), EditorConfig::ensure_config_dirs()

Files that now use config_paths directly: theme.rs, keymap/defaults.rs, config.rs, model/mod.rs, update/app.rs

The config_paths module has its own unit tests. There are also tests in:
- src/config.rs has tests in a #[cfg(test)] mod tests block
- src/keymap/defaults.rs has tests in a #[cfg(test)] mod tests block

These inline tests could potentially be moved to the tests/ folder for consistency with the project's integration tests.
