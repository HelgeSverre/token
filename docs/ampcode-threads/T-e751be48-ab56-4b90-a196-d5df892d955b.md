I just completed implementing Multi-Cursor Selection Gaps - making SelectWord, SelectLine, SelectAll, and ExtendSelectionToPosition work properly with multiple cursors.

Key implementations completed:
- merge_overlapping_selections() in EditorState - merges overlapping/touching selections, maintains invariants (cursors.len == selections.len, cursor[i].to_position() == selection[i].head)
- SelectWord now operates on ALL cursors using word_under_cursor_at(doc, idx) helper, then calls merge_overlapping_selections()
- SelectLine now operates on ALL cursors, then merges overlapping
- SelectAll properly collapses to single cursor + single full-document selection
- ExtendSelectionToPosition collapses multi-cursor first, then extends from primary cursor

Architectural patterns I followed:
- EditorState has cursors: Vec<Cursor> and selections: Vec<Selection> (parallel arrays)
- Per-cursor primitives like move_cursor_left_at(doc, idx) and word_under_cursor_at(doc, idx) in EditorState
- All-cursors wrappers like move_all_cursors_left(doc)
- Multi-cursor editing processes cursors in reverse document order to avoid offset shifting (cursors_in_reverse_order helper)
- After multi-cursor operations that may cause overlaps, call deduplicate_cursors() for point collisions or merge_overlapping_selections() for selection overlaps

The codebase uses Elm Architecture: Msg -> update() -> Cmd -> render. Messages are in src/messages.rs (EditorMsg, DocumentMsg, etc.), handlers in src/update.rs.
