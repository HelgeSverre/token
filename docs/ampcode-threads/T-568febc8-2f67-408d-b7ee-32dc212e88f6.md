I just implemented three features for the Token text editor:

1. Expand/Shrink Selection (Option+Up/Down):
- Added selection_history field to EditorState for tracking selection expansion levels
- Added ExpandSelection and ShrinkSelection messages to EditorMsg
- Expand progression: cursor → word → line → all document
- Shrink pops from history to restore previous selection
- Selection history is cleared when user moves cursor or uses other selection commands
- Added 18 tests in tests/expand_shrink_selection.rs

2. Fixed RemoveCursor implementation:
- Was a TODO stub, now actually removes cursor at specified index
- Protects against removing the last cursor (must always have at least one)

3. Cursor sync across views:
- When a document is edited in one split view, cursors in other views of the same document are adjusted
- Added adjust_other_editors_cursors() method to EditorArea
- Added sync_other_editor_cursors() helper in update.rs
- Currently implemented for single-cursor InsertChar, InsertNewline, DeleteBackward, DeleteForward
- Multi-cursor operations don't yet sync (would need more complex tracking)
- Added 4 cursor sync tests in tests/layout.rs

Key patterns I follow:
- TDD: write failing tests first
- Use saturating_sub for arithmetic to prevent overflow panics
- Elm architecture: Message → Update → Cmd → Render
- Tests use test_model() helper from tests/common/mod.rs
- EditorState has parallel cursors/selections vectors (invariant: same length)

The selection_history field was added to EditorState, requiring updates to all places that construct EditorState (model/editor.rs, main.rs test helper, tests/common/mod.rs).

Current test count: 369+ tests (351 baseline + 18 expand/shrink + 4 cursor sync)

Deferred/incomplete items:
- Multi-cursor cursor sync (only single-cursor edits sync currently)
- Cursor sync for selections (not just cursors)
- Cursor sync for complex operations like DeleteLine, Duplicate, etc.
