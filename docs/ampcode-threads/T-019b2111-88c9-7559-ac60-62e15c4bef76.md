I implemented a comprehensive keymapping system migration from hardcoded input handling to a YAML-configurable system:

Keymapping System (Phases 1-6 complete):
- New src/keymap/ module with types (Modifiers, KeyCode, Keystroke), Command enum (60+ variants), Keybinding, Keymap, and context system
- YAML config parser loads bindings from keymap.yaml at project root (embedded at compile time via include_str!)
- Platform-aware "cmd" modifier maps to Meta on macOS, Ctrl elsewhere
- Bridge integration in app.rs tries keymap first for simple commands, falls back to input.rs for complex behaviors
- Chord support with KeyAction::{Execute, AwaitMore, NoMatch}
- Context system: KeyContext struct with has_selection, has_multiple_cursors, modal_active, editor_focused
- Condition enum: HasSelection, NoSelection, HasMultipleCursors, SingleCursor, ModalActive, ModalInactive, EditorFocused
- YAML supports when: ["condition1", "condition2"] for conditional bindings
- Tab and Escape now use context-aware bindings (Tab indents with selection, inserts tab without; Escape cascade: multi-cursor → selection → nothing)

Modal Isolation:
- Keymap dispatch is skipped when modal is active - keys go to modal handler in input.rs instead
- Added 9 tests verifying modals don't leak to editor (arrow keys, typing, backspace, delete, enter, escape, pageup/down, home/end, cmd shortcuts)

Focus-aware Cursor Visibility:
- Added is_group_focused() helper to EditorArea
- Cursors only render in focused editor pane (is_focused && cursor_visible check in render_text_area)
- Fixed tab bar click-through by replacing global is_in_tab_bar(y) with per-group is_in_group_tab_bar(y, &group.rect)
- Fixed cursor icon and middle-click handling for all tab bars in splits

What still lives in input.rs (needs migration):
- Selection collapse on arrow keys (jump to selection start/end before moving)
- PageUp/Down with selection (normalize selection first)
- Option double-tap for multi-cursor (temporal pattern, not a chord)
- Arrow key context-dependent behaviors

The implementation plan is in docs/feature/KEYMAPPING_IMPLEMENTATION_PLAN.md and needs updating. Remaining phases per that doc:
- Phase 7: Migrate complex behaviors using context conditions
- Phase 8: Modal integration
- Phase 9-11: User config file loading, cleanup
