## Assistant

**Conditional compilation for debug vs release builds:**

- `#[cfg(not(debug_assertions))]` → `render_impl` — lean version for **release** builds
- `#[cfg(debug_assertions)]` → `render_impl_with_perf` — includes performance timing instrumentation for **debug** builds

The debug version tracks timing for each render phase (`clear_time`, `text_time`, `status_bar_time`, `present_time`) and can show a performance overlay. The release version skips all that overhead for maximum speed.

## User

at the expense of massive code duplication?

## Assistant

You're right — it's a code smell. The two implementations are nearly identical except for `Instant::now()` / `.elapsed()` calls.

Better approaches:

1. **No-op timing in release** — a `PerfStats` that compiles to zero-cost in release:
   ```rust
   #[cfg(not(debug_assertions))]
   impl PerfStats {
       #[inline(always)]
       pub fn time<T>(&mut self, _phase: Phase, f: impl FnOnce() -> T) -> T { f() }
   }
   ```

2. **Macro wrapper** — `time_phase!(perf, clear_time, { ... })` that expands to timing or passthrough.

3. **Single implementation** with `#[cfg]` on individual timing calls instead of duplicating the whole method.
