I'm cleaning up multi-cursor support in a Rust text editor. I've been fixing bugs where operations only work on the primary cursor instead of all cursors.

Key patterns I established:
- Operations that should work on all cursors check has_multiple_cursors() first
- For line-based operations (DeleteLine, Indent, Unindent), use lines_covered_by_all_cursors() helper which returns unique lines in reverse document order
- Multi-cursor edits wrap in EditOperation::Batch with cursors_before/cursors_after for proper undo
- Delete/modify lines from bottom to top (reverse order) to avoid offset invalidation

I just fixed DeleteLine (Bug #25) using this pattern. The bugtracker shows Bug #5 (Indent) and Bug #6 (Unindent) are still open and need the same treatment.

From the Oracle analysis, these line-based operations:
- Currently only use primary_cursor()/primary_selection()
- Should collect unique lines from all cursors/selections
- Process in reverse document order
- Use the lines_covered_by_all_cursors() helper I already added

The helper is in src/update/editor.rs and is already imported in src/update/document.rs. It handles both cursor positions and selection ranges, returning unique lines sorted highest-first.

The bugtracker at docs/multi-cursor-bugtracker.md tracks all issues and should be updated when fixes are complete.

### Remaining Multi-Cursor Issues

#### Critical: Bug #3 - Undo Loses Multi-Cursor State

**Problem:** When you have 3 cursors and type a character, then press Undo, only the primary cursor is restored - the other 2 cursors disappear.

**Why:** Non-Batch `EditOperation` variants (Insert, Delete, Replace) only store `cursor_before`/`cursor_after` for a single cursor. Multi-cursor edits use `Batch` which stores full `cursors_before`/`cursors_after` vectors, but single-cursor edits don't benefit from this.

**Fix:** Either always use Batch for edits, or add full cursor vectors to all EditOperation variants.

---

#### High: Bug #4 - Duplicate Only Works on Primary

**Problem:** With 3 cursors on different lines, pressing Cmd+D only duplicates the line at the first cursor.

**Why:** `DocumentMsg::Duplicate` reads `primary_cursor()` and `primary_selection()` directly.

**Fix:** Same pattern as IndentLines - iterate all cursors in reverse document order, duplicate at each position.

#### Medium: Bug #11 - delete_selection Helper is Single-Cursor

**Problem:** The `delete_selection()` helper in `editor.rs` only handles `primary_selection()`.

**Why:** It was written before multi-cursor. Call sites use it for "delete selection then insert" patterns.
