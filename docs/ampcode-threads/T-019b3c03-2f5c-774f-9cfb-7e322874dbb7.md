I completed a performance optimization pass on the Token editor, addressing a major issue where the app showed ~7 FPS in multi-split scenarios while headless benchmarks showed ~380 FPS.

Key optimizations I implemented:
- Changed ControlFlow::Poll to ControlFlow::WaitUntil in src/runtime/app.rs to stop the event loop from spinning continuously. The app now sleeps until the next cursor blink timer (500ms) and wakes immediately for input/async messages.
- Fixed HiDPI scaling issues in the debug performance overlay (src/runtime/perf.rs) - hard-coded pixel values weren't scaling properly on Retina displays. Added scale factor based on line_height.
- Fixed a subtraction overflow panic in perf.rs line 345 by using saturating_sub.

Profiling results from a 30-second real-world session showed:
- 77.6% idle/waiting (mach_msg2_trap) - confirms WaitUntil fix is working
- 21.5% event handling (CFRunLoop overhead)
- ~0.9% actual rendering code
- Memory: 93MB footprint, 180MB peak

The profiling workflow I used:
1. Build with: cargo build --profile profiling
2. Run Apple's sample command: sample $PID 30 -file /tmp/token-sample.txt
3. Or use xctrace: xcrun xctrace record --template "Time Profiler" --time-limit 60s --launch ./target/profiling/token
4. Symbolicate with: xcrun xctrace symbolicate --input trace.trace --dsym ./target/profiling/token
5. For quick analysis, samply is also available: samply record ./target/profiling/token
